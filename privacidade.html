Escopo e papéis

O Sistema de Pedidos fornece ferramentas para lojistas criarem cardápios e gerenciarem configurações de lojas. Para cadastro, autenticação e operação do painel, o operador do Sistema trata dados da conta e da loja. Nas lojas de clientes, o lojista que recebe os pedidos decide como usar os dados do consumidor e atua como controlador desses dados. O papel contratual do operador do Sistema em cada fluxo deve ser validado e formalizado antes da publicação desta política.

Dados tratados e finalidades

  • Conta: UID, e-mail, nome e foto associados à autenticação por e-mail ou Google, para criar e proteger a conta. Credenciais são tratadas pelo Firebase Authentication; o código não copia a senha para o documento de perfil.
  • Loja: configurações, cardápio, contatos e imagens enviados pelo lojista, para editar e publicar a loja.
  • Pedido: no modelo de cardápio, dados digitados pelo consumidor são usados no dispositivo para compor o pedido e, quando o consumidor aciona o link, são incluídos na mensagem destinada ao WhatsApp da loja. O operador do Sistema não recebe o conteúdo do pedido pelo código do cardápio estático examinado.
  • Dados técnicos: provedores de hospedagem, autenticação e infraestrutura podem registrar dados de conexão e operação. Conteúdo, região, acesso e retenção precisam ser confirmados nas configurações e contratos dos fornecedores.

Compartilhamento e fornecedores

O código utiliza Firebase Authentication, Firestore e Cloud Storage, serviços do Google; autenticação Google quando escolhida pelo usuário; Cloudflare CDNJS para bibliotecas técnicas de exportação e QR Code no painel; e links do WhatsApp para envio voluntário de pedidos. As fontes e imagens remotas de apresentação foram removidas do carregamento desta versão. Fornecedor, categorias de dados, localização e retenção devem ser conferidos nos painéis e contratos antes da publicação.

Armazenamento e retenção

Perfis e dados de lojas são gravados no Firebase. Imagens são enviadas ao Cloud Storage. Arquivos de imagem podem permanecer após a exclusão de uma loja para não quebrar sites já exportados. Prazos de retenção de contas, logs, backups e dados de fornecedores ainda precisam ser definidos e documentados; esta política não promete exclusão de backups ou de sistemas de terceiros antes dessa confirmação.
